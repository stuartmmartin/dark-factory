# dark_factory docs

## Reading orders

- **New engineer:** [`environment_setup.md`](environment_setup.md) → [`architecture/overview.md`](architecture/overview.md) →
  [`architecture/monorepo.md`](architecture/monorepo.md) →
  [`architecture/clean-architecture.md`](architecture/clean-architecture.md) → `adr/`.
- **AI agent:** [`/AGENTS.md`](../AGENTS.md) → path-scoped `.claude/rules/` →
  [`agents/README.md`](agents/README.md) → [`conventions/architecture.md`](conventions/architecture.md),
  [`conventions/coding.md`](conventions/coding.md), [`conventions/testing.md`](conventions/testing.md) →
  `generated/module-index.md` → the service's `CLAUDE.md` and `CONTEXT.md`.
- **Reviewer of an AI PR:** [`guides/reviewing-ai-prs.md`](guides/reviewing-ai-prs.md) → the PR's use case docstrings
  (`R<n>` rules) and the matching `test_R<n>_*` tests.

## Map

| Path | What |
|---|---|
| `architecture/` | How the pieces fit together: [monorepo](architecture/monorepo.md), [clean architecture](architecture/clean-architecture.md), [data](architecture/data.md), [messaging](architecture/messaging.md), [workflows](architecture/workflows.md), [admin](architecture/admin.md), [overview](architecture/overview.md), [deployment](architecture/deployment.md) |
| `conventions/` | The single source of rules, with IDs (A*, C*, T*) |
| `guides/` | Task how-tos: [add a service](guides/add-a-service.md), [add a use case](guides/add-a-use-case.md), [review AI PRs](guides/reviewing-ai-prs.md) |
| `agents/` | How the AI scaffolding works: context layering, hooks, skills, review gates, dark-factory runbook |
| `adr/` | Architecture decision records |
| `generated/` | Build graph and module index; **generated by `make graph`, verified in CI, never edited** |

Working docs (specs, plans, ledgers, reviews) are never committed. They go in gitignored
`.work/<slug>/`, and the `harvest` skill moves what lasts into code, tests and the docs above.
